# Chrome ウェブストア 申請チェックリスト

Account Deck for AWS 2.0.0 を Chrome ウェブストアに出すときの手順です。上から順に進めてください。各欄に貼る文面は [listing.md](listing.md) にあります。

公式の手順: [Register](https://developer.chrome.com/docs/webstore/register) / [Publish](https://developer.chrome.com/docs/webstore/publish) / [Privacy タブ](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy)（2026-10-17 に確認）

## 0. 申請の前に

- [ ] PR #1（`ft/account-deck-v2` → `main`）をマージした。プライバシーポリシーの URL（下の 4.）は main にないと開けない
- [ ] 本物の AWS で動作を確かめた（`chrome://extensions` → デベロッパーモード → 「パッケージ化されていない拡張機能を読み込む」で `src/` を選ぶ）
  - [ ] ログイン環境の「開く」で、アカウントID・ユーザー名・パスワードが入る
  - [ ] スイッチロールの「開く」で、Switch Role ボタンが押されて切り替わる
  - [ ] マスターパスワードを設定 → ロック → ポップアップから解除して開ける
- [ ] `npm run package` で `dist/account-deck-for-aws-2.0.0.zip` を作り直した（`src/` を変えたら毎回）

## 1. デベロッパー登録（初回だけ）

- [ ] [デベロッパー ダッシュボード](https://chrome.google.com/webstore/devconsole) に、公開に使う Google アカウントでログインする
- [ ] デベロッパー契約とポリシーに同意し、登録料（1回だけ）を払う。金額は画面の表示で確かめる（公式ドキュメントには金額が書かれていない）
- [ ] デベロッパーのメールアドレスを決める（あとから変えられない）
- [ ] 2段階認証を求められたら有効にする

## 2. パッケージ

- 名前・概要・アイコンは manifest から入る（英語と日本語は `_locales` から）

## 4. プライバシー（Privacy）

- [ ] 単一用途の説明（Single purpose）:

  ```text
  Open AWS Management Console sign-in pages and switch-role pages that the user has registered, and fill in the user's saved sign-in details on the AWS sign-in page.
  ```

- [ ] 権限の理由:
  - `storage`:

    ```text
    Stores the environments the user registers (display name, account ID, sign-in URL, IAM user name, role name, color, label) and the user's settings on this device. Saved passwords are encrypted with AES-GCM before they are stored.
    ```

  - ホスト権限（content script の `https://signin.aws.amazon.com/*`、`https://*.signin.aws.amazon.com/*`）:

    ```text
    Needed only on AWS sign-in pages: to fill in the account ID, user name and password the user saved when they open an environment from the extension, and to press the Switch Role button on the switch-role page. The scripts do nothing unless the tab was opened from the extension.
    ```

- [ ] リモートコード: 「いいえ、リモートコードを使用していません」
- [ ] データの使用（収集するデータの種類）: 「認証情報」（Authentication information）にチェック。端末内に保存するだけでも申告の対象になる（User Data FAQ 3・4）
  - 迷ったら追加でチェックする候補: 「個人を特定できる情報」（IAM ユーザー名・アカウントID をこれに含めるかは判断が分かれる。審査で指摘されたら足す）
- [ ] 下の3つの宣誓にチェック（第三者への販売・転送をしない、目的と関係のない利用をしない、信用力の判断に使わない）
- [ ] プライバシーポリシーの URL: `https://github.com/htani0817/account-deck-for-aws/blob/main/PRIVACY.md`

## 6. テストの手順（Test instructions）

AWS アカウントが無くても審査できるよう、次の文面を貼る:

```text
No account or credentials are needed to review the extension.

1. Open the extension's options page. On first run, a welcome page asks how to protect saved passwords; choose either option.
2. Add a "Sign-in" environment with any 12-digit account ID (for example 111122223333), any user name and any password.
3. Open the popup and press Open. The extension opens https://111122223333.signin.aws.amazon.com/console, fills in the account ID, user name and password on the AWS sign-in page, and presses Sign in once. With made-up values AWS shows a sign-in error, which is expected. To see the fields being filled without signing in, leave the password empty: the extension then only fills the form.
4. A "Switch role" environment opens https://signin.aws.amazon.com/switchrole with the account ID and role name and presses Switch Role. This step requires being signed in to the AWS console, so it may show an error page without an account; that is expected.
```
